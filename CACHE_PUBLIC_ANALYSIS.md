# Анализ Cache-Control для файлов из public/

## 1. Какие файлы из public попадают под правило статики

Правило в next.config:
```ts
source: "/(.*)\\.(svg|png|jpg|jpeg|webp|avif|ico|woff2|woff|ttf|eot|js|css)"
```

**Текущее содержимое public/:**

| Файл | Расширение в правиле | Попадает под правило | Имя версировано/хеш? |
|------|----------------------|----------------------|-----------------------|
| `file.svg` | svg ✓ | Да | Нет |
| `window.svg` | svg ✓ | Да | Нет |
| `liteh-logo.svg` | svg ✓ | Да | Нет |
| `vercel.svg` | svg ✓ | Да | Нет |
| `yandex_7261bff043c5354b.html` | html ✗ | Нет | Строка похожа на id, но не хеш контента |
| `robots.txt` | txt ✗ | Нет | — |

Под «long cache» (текущее значение `immutable`) попадают только: **file.svg**, **window.svg**, **liteh-logo.svg**, **vercel.svg**.

---

## 2. Могут ли эти файлы обновляться без смены имени?

| Файл | Может обновляться без смены имени? | Риск immutable |
|------|------------------------------------|----------------|
| `liteh-logo.svg` | Да (обновление логотипа) | Высокий — старый лого может кешироваться до года |
| `file.svg`, `window.svg`, `vercel.svg` | Теоретически да (правки иконок/иллюстраций) | Средний — контент может меняться при том же имени |

Ни у одного из этих файлов в имени нет версии или хеша контента (как у `_next/static/.../chunk-[hash].js`). Имена стабильные, контент при деплое может меняться → **immutable для них небезопасен**.

---

## 3. Где immutable безопасен, где рискован

- **Безопасно:**  
  **`/_next/static/:path*`** — пути содержат хеш сборки/контента, при новом деплое меняется URL. Старый URL можно кешировать на год без риска отдать устаревший контент. Оставляем `public, max-age=31536000, immutable`.

- **Рискованно:**  
  Файлы из **public/** с именами без версии/хеша (все текущие .svg). При смене содержимого под тем же именем браузер с `immutable` может год отдавать старую версию. Для них нужен **неагрессивный** вариант: кеш на ограниченное время + revalidate.

---

## 4. Рекомендация

- **Страницы:** оставить `public, max-age=0, must-revalidate`.
- **`/_next/static/:path*`:** оставить `public, max-age=31536000, immutable`.
- **Правило для public (расширения .svg, .png, .woff2 и т.д.):** заменить значение на **`public, max-age=86400, must-revalidate`** (1 день кеш, затем повторная проверка). Имена в public не версированы — использовать для них `immutable` не стоит.

В public сейчас нет файлов с хешем в имени; если позже появятся (например `logo.[contenthash].svg`), для них при желании можно добавить отдельное правило с `immutable`. Сейчас достаточно одной безопасной политики для всех подпадающих под расширения файлов из public.
